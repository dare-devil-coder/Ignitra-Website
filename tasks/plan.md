# Build plan

## Governing decisions

Preserve the source's eight-section main order and all alternate states. Next.js static export is the foundation; consultation delivery requires a separate backend adapter or the original server implementation. Never port legacy JS, CSS, SVG scene geometry or component structure. Use copied brand assets/posters and existing fonts. The Stage 1 content ledger is temporary proof infrastructure, not the new design.

## Stage 1 — GPT-6-Astra / High

1. Audit source, screenshots, assets and client interactions. Acceptance: screenshots at 375/768/1440/1920, exact section map, no live submissions.
2. Extract content and independent source snapshots before UI. Acceptance: flat semantic records, alternate states and metadata, SHA-256 protected baseline, no copy exceptions.
3. Scaffold and tokens. Acceptance: static build, strict types, lint, verifier mutation tests, actual DOM content checks in both themes; preserve all source fonts and assets.
4. Document and commit. Acceptance: complete handoff and next-stage plan, design schema lint/export, measured contrast, main plus build/from-scratch. Dependencies: all prior tasks.

## Stage 2 — GPT-6.1-Sol

1. Read AGENTS, HANDOFF, SECTION_MAP, site-content; reselect frontend/responsive/accessibility skills. Replace ContentLedger with typed section composition. Build Container, Section, Heading, Button and Card first; only add other primitives when existing content needs them.
2. Build navigation, mobile menu and hero in both themes. Use original labels and local logo/rocket posters. Theme toggle gets aria-pressed, accessible name from the JSON, keyboard behavior, storage and system-default tests. No scroll motion.
3. Build problem comparison, difference loop and services in locked order. Use the existing loop names/descriptions; keyboard and touch select states. No invented stats or service CTA labels.
4. Build engine, reasons and brief. Mobile/reduced-motion shows all seven steps; desktop static state selection exposes the same content before scroll motion is added. Keep all original pending/final brief labels.
5. Build CTA, footer and consultation dialog. Preserve literal href/target and source field constraints. Implement native or accessible custom selection without losing option hints. Close with Escape, trap focus while open, restore the trigger. Do not submit test leads to production.
6. Resolve backend parity using original Server Action source or an approved separate free endpoint and its environment variables. Never hard-code the public deployment action ID into a replacement API. Preserve success/error strings after obtaining server evidence; never show success for an unsent request. This is the only functional dependency requiring owner input.
7. Extend verify-content to open/select the stored interaction states and compare real rendered copy, links, labels and form options against the independent source evidence. All source data must remain unchanged. Test dark/light at 360/768/1024/1440/1920, keyboard, no-flash loading, storage blocked and system preference. Commit and hand off.

## Stage 3 — GPT-6-Astra / High

1. Reselect GSAP, Lenis, 3D and motion-performance skills. Define one lifecycle and teardown owner. Implement deferred imports, synchronized ticker, ScrollTrigger cleanup and a no-motion static path.
2. Implement a short non-text intro and hero reveal. Preserve the rocket signature using an independently authored scene/model. The old scene is procedural; no public GLB was found. Prefer a newly compressed GLB for the new R3F/drei scene. Use existing theme-specific posters on small/low-power/reduced-motion devices. No new visual branding.
3. Choreograph the engine with bounded scrub/pinning, never the source's large empty full-page span. Keep reading order and keyboard access. Refresh on font/layout changes without recreating the scene on theme switch.
4. Add restrained section reveals, image wipes, glows, progress, magnetic primary CTAs and fine-pointer cursor. Use current on-screen state on interruption. No animation of layout properties except the explicitly requested accordion height if a real accordion is discovered.
5. Add circular theme reveal with reduced-motion instant switch and fallback color fade. Tune grain/glow/scene lights independently per theme. Recheck every content state after animation settles. Commit and hand off.

## Stage 4 — GPT-6.1-Sol

1. Reselect browser, accessibility, performance and code-review skills. Optimize original images while preserving alt/order; explicit sizes and lazy loading below fold. Resolve the Lighthouse development dependency advisories before using downloaded-browser workflows.
2. Audit both themes and breakpoints, keyboard/zoom/reduced motion, console, content gates, form behavior with mocked/local endpoints, and real deployment backend only after owner authorization.
3. Capture final screenshots in docs/after with dark-/light- prefixes; record scroll video/frames and inspect for jank/pop-in/pinning. Lighthouse mobile target >=85, LCP <2.5s, CLS <0.1. Report actual measurements and unmet targets honestly.
4. Produce the final Design Report through the requested retained DOCX template; use the installed documents capability, clone reference, render and visually inspect before delivery. Update handoff/changelog, verify content, commit. Do not push/deploy unless requested.

## Effect applicability

- Implement: non-text intro, hero reveal/rocket idle/parallax where allowed, Lenis, bounded engine storytelling, section/image reveals, restrained glow parallax, progress bar, fine-pointer cursor, magnetic primary buttons, hover states, grain, single compounding-effect light break and theme reveal.
- No count-up business statistics: source numbers are ordered step indices, year, phone/address/legal identifiers, not statistics. Never animate those values from zero.
- No marquee: no existing client/logo strip.
- No FAQ accordion: source has none. Interactive process loop is not an excuse to invent FAQ copy.
- No route wipe: one public route. Anchor navigation remains functional.
- Horizontal/pinned showcase: engine only when desktop bounds and keyboard reading remain correct; no added sections or reordered cards.

## Risks

Content completeness is limited by private server behavior; ask for backend source/config before functional completion. Opaque posters may show seams on the new cream; use correct variants and a transparent scene later. Legacy full-page pin screenshots are not enough to prove motion correctness. Avoid paid generation and preserve the supplied visual direction if Superdesign authentication remains unavailable.
